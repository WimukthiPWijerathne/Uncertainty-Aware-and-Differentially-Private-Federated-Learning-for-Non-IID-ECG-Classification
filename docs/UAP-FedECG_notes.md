# UAP-FedECG — glossary

## Glossary

| Term                                      | Meaning                                                                                                                                                                                                                                                                                                                 |
| ----------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Federated learning (FL)                   | Training one shared model across multiple parties (hospitals) without any party sharing its raw data. Only model weights/updates move between them.                                                                                                                                                                     |
| Client                                    | One participant in FL — here, a hospital with its own private ECG data and its own local model.                                                                                                                                                                                                                         |
| Global model                              | The shared model living on the central server. Gets sent out to clients, updated from their feedback, repeat.                                                                                                                                                                                                           |
| Local model                               | A client's own copy of the model after training on its private data for a few epochs.                                                                                                                                                                                                                                   |
| Communication round                       | One full cycle: server sends global model → clients train locally → clients send updates back → server aggregates. Repeated many times.                                                                                                                                                                                 |
| FedAvg (Federated Averaging)              | The standard aggregation rule: new global weights = weighted average of all clients' weights, weighted by how many samples each client has (`w_global = Σ(n_k · w_k) / Σn_k`).                                                                                                                                          |
| IID                                       | "Independent and identically distributed" — the assumption that every client's data looks statistically the same (same label proportions, same feature distribution).                                                                                                                                                   |
| Non-IID                                   | When that assumption breaks — clients have meaningfully different data distributions. The core problem this project addresses.                                                                                                                                                                                          |
| Label skew                                | One type of non-IID: different class proportions across clients (e.g. Hospital A mostly normal ECGs, Hospital B mostly heart attacks).                                                                                                                                                                                  |
| Quantity skew                             | Different amounts of data per client (one hospital has 8,000 records, another has 300).                                                                                                                                                                                                                                 |
| Feature skew                              | Same labels, but signals look different across clients due to different equipment, sampling rates, lead placement, etc.                                                                                                                                                                                                 |
| Client drift                              | The failure mode where averaging models trained on very different (non-IID) local data produces a global model worse than the individual local models, because they learned to solve different problems.                                                                                                                |
| Predictive uncertainty                    | How stable/confident a model's prediction is for a given input — not "does it know the answer" but "would it keep giving the same answer if asked slightly differently."                                                                                                                                                |
| Dropout                                   | A training-time regularization trick: randomly zero out a percentage of neurons on each training step so the network doesn't over-rely on any one neuron. Normally switched off at inference.                                                                                                                           |
| MC dropout (Monte Carlo dropout)          | Keeping dropout switched ON at inference time and running the same input through the network multiple times. Each pass randomly drops different neurons, giving slightly different outputs. The spread (variance) across those outputs is the uncertainty estimate — tight spread = confident, wide spread = uncertain. |
| Uncertainty-aware aggregation (UA-FedAvg) | This project's core contribution: instead of weighting clients only by sample count, also weight by their model's uncertainty, so confident/stable hospitals get more influence and shaky ones get down-weighted — regardless of data volume.                                                                           |
| Differential privacy (DP)                 | A mathematical guarantee bounding how much any single patient's record could have influenced the model's output, added on top of FL for extra protection since raw weights can still leak some information.                                                                                                             |
| Gradient clipping                         | Capping how much any single training example's gradient can influence an update, so one outlier record can't dominate. Used as part of DP training.                                                                                                                                                                     |
| Epsilon (ε)                               | The "privacy budget" in DP. Smaller ε = more noise added = stronger privacy guarantee = worse model accuracy. This is the core privacy–utility tradeoff.                                                                                                                                                                |
| Opacus                                    | The library used to add DP to local training (gradient clipping + calibrated noise).                                                                                                                                                                                                                                    |
| Flower                                    | The framework used to implement the actual FL server/client communication loop.                                                                                                                                                                                                                                         |
| PTB-XL                                    | The ECG dataset the project is built on; ~21k recordings, standard benchmark, gets artificially split into "hospitals" (there's no clean real per-hospital split, so partitioning is usually done via Dirichlet sampling over labels).                                                                                  |
| 1D-CNN                                    | The model architecture — a convolutional network adapted for 1D time-series signals like ECG, instead of 2D images.                                                                                                                                                                                                     |

## In a nutshell — what we covering

**The project (UAP-FedECG):** simulate multiple hospitals training one shared ECG classifier via federated learning, without sharing patient data. The twist: use model uncertainty (not just data volume) to decide how much to trust each hospital's update during aggregation, and layer differential privacy on top.

**Scope reality check:** the full README (10 objectives incl. ablations, full calibration/fairness/DP analysis) is a paper's worth of work. For a 4-person team with ~10-11 days, the plan is: centralized baseline → non-IID partitioning → vanilla FedAvg → MC dropout + uncertainty-aware aggregation (the real contribution, protect this) → DP as a stretch goal attempted last, not a hard requirement. Cut ablation study and deep fairness/calibration sections; fold into one combined results discussion.

**How FL actually works:** server holds a global model → sends it to every hospital → each hospital trains locally on its own private ECGs → hospitals send back only weight updates (never data) → server averages the updates into a new global model → repeat for many rounds. Standard FedAvg weights each hospital's contribution just by how many samples it had.

**Why that breaks (non-IID):** real hospitals don't have statistically similar data. One hospital might be 70% normal ECGs, another 60% heart attacks. Averaging models trained on such different distributions can produce a global model worse than either local model alone — "client drift." Sample count is a bad proxy for how trustworthy a hospital's update actually is.

**The fix this project explores — uncertainty-aware aggregation:** use MC dropout to measure how confident each hospital's local model is. Keep dropout on at inference, run the same input through the network multiple times (each pass randomly zeroes different neurons), and look at how much the output varies. Tight, consistent outputs = confident model = low uncertainty. Scattered, inconsistent outputs = shaky model = high uncertainty. Feed that uncertainty into the aggregation formula so confident hospitals get more say than plain FedAvg would give them, and shaky ones get less — independent of how much data they had.

**Differential privacy, bolted on separately:** even sharing only weights can leak information about individual patients. DP bounds this by clipping gradients and adding calibrated random noise during local training, controlled by a privacy budget ε. Smaller ε = stronger privacy but worse accuracy. Expect this tradeoff to bite harder than usual here, since DP noise compounds with non-IID client disagreement — treat degraded accuracy under DP as an expected, reportable finding rather than a bug to chase.
